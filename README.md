# ものがたり紙芝居 v1.9.0

小説（2万5千字程度）を AI が場面に分け、漫画風の絵と Gemini TTS の朗読で「紙芝居」として上演・動画書き出しする Web アプリです。

## ファイル構成

```
monogatari-kamishibai/
├─ index.html        画面
├─ style.css         デザイン
├─ app.js            画面の動き（認証・編集・生成・上演・録画）
├─ config.js         GAS URL などの設定
├─ export-worker.js  動画の高速書き出し（Web Worker）
├─ lib/
│  ├─ mp4-muxer.js   MP4 組み立てライブラリ（MIT）
│  └─ webm-muxer.js  WebM 組み立てライブラリ（MIT）
└─ gas/
   ├─ Code.gs        GAS バックエンド（会員・Gemini・Drive）
   └─ appsscript.json
```

## データの流れ

| 役割 | 保存先 |
|---|---|
| 会員情報（ハッシュ化パスワード・同意日時） | スプレッドシート「ものがたり紙芝居_会員」/ Users シート |
| 作品（本文・場面・人物） | Drive「ものがたり紙芝居_data / u_xxx / p_作品ID / project.json」 |
| 場面の絵・三面図・背景参考・作風の参考絵・朗読 WAV | 同じ作品フォルダ |
| 取り込んだ朗読ファイル | 同じ作品フォルダに 4MB ずつ分割（`narr_…_0000` …） |

## セットアップ手順

### 1. GAS プロジェクトを作る
1. https://script.google.com で「新しいプロジェクト」を作成し、名前を `monogatari-kamishibai` にします。
2. `Code.gs` の中身を `gas/Code.gs` で置き換えます。
3. 「プロジェクトの設定」→「appsscript.json をエディタで表示する」をオンにし、`gas/appsscript.json` で置き換えます。
   （clasp を使う場合は `gas/` フォルダで `clasp create` → `clasp push`）

### 2. API キーとモデルを設定する
「プロジェクトの設定」→「スクリプト プロパティ」に追加します。

| プロパティ | 値 | 必須 |
|---|---|---|
| `GEMINI_API_KEY` | Google AI Studio で発行したキー | 必須 |
| `APP_URL` | 公開ページの URL（例 `https://kenken6291.github.io/monogatari-kamishibai/`）。仮パスワードのメールに載ります | 任意 |
| `TEXT_MODEL` | 場面解析用（既定 `gemini-2.5-flash`） | 任意 |
| `IMAGE_MODEL` | 画像生成用（既定 `gemini-2.5-flash-image`） | 任意 |
| `TTS_MODEL` | 朗読用（既定 `gemini-2.5-flash-preview-tts`） | 任意 |
| `ALIGN_MODEL` | 字幕同期用（未設定なら `TEXT_MODEL` と同じ） | 任意 |

新しいモデルに切り替えるときは、コードを触らずにこのプロパティだけ書き換えれば反映されます。

### 3. 初回セットアップを実行する
エディタ上部の関数選択で `setup` を選んで「実行」→ 権限を承認します。
Drive に `ものがたり紙芝居_data` フォルダと会員スプレッドシートが作られ、ID がスクリプトプロパティ（`ROOT_FOLDER_ID` / `SPREADSHEET_ID`）に自動で入ります。

### 4. ウェブアプリとしてデプロイする
「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
- 次のユーザーとして実行：**自分**
- アクセスできるユーザー：**全員**

発行された `https://script.google.com/macros/s/…/exec` をコピーします。
コードを更新したら「デプロイを管理」→ 鉛筆アイコン →「新バージョン」で同じ URL のまま更新できます。

### 5. フロントエンドを GitHub Pages に公開する
1. リポジトリ `monogatari-kamishibai` を作り、`index.html` `style.css` `app.js` `config.js` を置きます（`gas/` は入れても動作に影響しません）。
2. `config.js` の `GAS_URL` に手順4の URL を入れます。
3. Settings → Pages → Branch `main` / root で公開します。
4. 画面右上の「設定」からも GAS URL を上書きできます（その端末のブラウザに保存）。

### 6. 動作確認
1. 「新規登録」→ 4つの同意にチェック → 仮パスワードのメールが届く
2. 仮パスワードでログイン → パスワード変更画面が出る
3. 本文を貼る →「AIで場面に分ける」→「絵を一括生成」→「朗読を一括生成」→「上演する」

## 仕様メモ

- **場面数の算出**：本文を段落番号つきで Gemini に渡し、およそ700字に1枚を目安に、山場は細かく・説明部分はまとめるよう指示。返ってきた段落範囲はサーバー側で抜け・重なりを補正します。
- **画像サイズ**：横長 16:9 / 縦長 9:16 / 正方形 1:1。生成時に `imageConfig.aspectRatio` で指定し、上演キャンバスも同じ比率になります。
- **人物の一貫性**：人物ごとに特徴文と三面図（アップロードまたはAI生成）を保持し、その人物が出る場面の生成時に三面図を参照画像として最大3人分添付します。
- **Google Earth Studio 連携**：Earth Studio で書き出した風景の静止画を、場面ごとに「背景参考を入れる」で添付すると、その地形・構図を参考に漫画風の背景で描きます。
- **パン・スライド演出**：ゆっくり寄る／引く、上下左右へのパン、スライドで登場、動かさないの8種。AIが場面ごとに提案し、対応表で変更できます。場面の切り替えは0.8秒のクロスフェード。
- **朗読の指示語対策**：TTS には指示文を一切付けず本文だけを渡します。さらに青空文庫の注記・ルビ・記号と、冒頭の「〜を朗読してください」等の行を除去します（台詞中の同じ言葉は残します）。長い場面は600字ごとに分けて生成し、0.25秒の間を挟んで1つの WAV に結合します。
- **音声入力**：`continuous` で認識し、ブラウザが途中で切っても自動で再開します。`config.js` の `SPEECH_SILENCE_MS`（既定8秒）無音が続いたときだけ終了します。
- **動画書き出し**：上演中のキャンバスと音声を MediaRecorder で録画し WebM で保存します（Chrome 推奨。録画中はタブを表示したままにしてください）。
- **会員**：同意4項目必須、仮パスワードのメール通知、初回強制変更、再発行、表示/非表示切替、5回失敗で15分ロック。セッションは6時間。

## v1.1 既存の朗読音声の取り込み

「場面と生成」タブの「朗読の音声」で、音声の使い方を選びます。

- **作品まるごと1本の朗読**：「朗読ファイルを取り込む」（MP3・WAV・M4A・AAC・OGG・FLAC、300MBまで）。4MBずつ分割して Drive に保存し、まず文字数の比率で場面に仮に割り振ります。その後、次のどちらかで絵の切り替え位置を合わせます。
  - **AIで場面に合わせる**：Gemini に朗読を聞かせ、各場面の冒頭が読まれる時刻を推定します。見つからなかった場面や前後が逆転した値は、文字数の比率で補います。GAS の6分制限があるため、目安は1時間程度まで。MP3 か WAV が確実です。
  - **聞きながら区切る**：朗読を再生し、次の場面の冒頭でボタン（スペースキー）を押します。1倍〜2倍速で聞けます。途中で保存すると残りは比率で割り振ります。
  - **文字数の比率で合わせる**：区切りを比率による割り振りに戻します。
- **場面ごとに分かれた音声**：対応表の「朗読を取り込む」で1場面ずつ入れます（20MBまで）。AI生成の朗読と混在できます。

取り込んだ朗読ファイルで上演・動画書き出しをするときは、音声を流しながら再生位置に合わせて絵を切り替えます。

## v1.2 参考絵から作風を作る

「絵と声の設定」タブの「漫画の作風」で、参考絵を3枚まで読み込めます。

- **参考絵から作風を作る**：Gemini が参考絵の線・塗り・陰影・色調・デフォルメ度合いなどを読み取り、画風指示の文章にします。文章はあとから自由に直せます。
- **絵を描くたびに参考絵もAIに見せる**（初期値オン）：場面の絵と三面図を描くとき、参考絵を2枚まで添付し、タッチだけを真似るよう指示します。文章だけで十分なときはオフにすると、生成が少し軽くなります。
- 参考絵は、自分で描いた絵や、使ってよいと許された絵を使ってください。

## v1.3 全画面上演

「上演・書き出し」タブの「全画面で上演」で、舞台の絵を画面いっぱいに映して上演を始めます。

- 画面下の操作バー（前の場面／一時停止／次の場面／全画面を閉じる）は、2.5秒操作がないと消えます。マウスを動かすか画面に触れると再び出ます。
- キー操作：スペース＝再生・一時停止、←→＝前後の場面、F＝全画面の切り替え、Esc＝全画面を閉じる。
- スマホでは作品の形（横長／縦長）に合わせて画面の向きを固定します（対応端末のみ）。iPhoneなど要素の全画面に未対応のブラウザでは、画面いっぱいに広げる表示で代用します。
- 動画の書き出し中も全画面で表示できます。ただし、書き出し中は場面の移動と一時停止はできません。

## v1.4 字幕と音声の同期

字幕は文ごと（長い文は読点で分割）に表示し、その切り替え時刻を朗読の音声から決めます。

- 上演の準備時に音声の音量を20ミリ秒ごとに調べ、朗読の「間」（無音区間）を見つけます。
- 文字数の比率で見込んだ位置の近くにある間を、文の切れ目として採用します。採用した位置を基準に次の見込みを立て直すため、読む速さが途中で変わってもずれが積み重なりません。
- 場面の頭と終わりの無音は除いてから割り振ります。
- AI生成の朗読、場面ごとに取り込んだ音声、作品まるごとの朗読ファイルのどれでも働きます。
- 「字幕のタイミング」で、全体を0.3〜0.6秒早める／遅らせる微調整ができます（端末ごとに保存）。
- 字幕にはルビ《》や注記［＃］を表示しません。

## v1.5 AIによる字幕同期

v1.4 の「間の検出」だけでは、朗読と本文の読み方の違いや、間の少ない朗読でずれが残るため、AIで実際に聞いて合わせる方式を追加しました。

- 「場面と生成」タブの「AIで字幕を音声に合わせる」を押します。
- 朗読を2分半ずつ（16kHzモノラルWAVに変換して）AIに聞かせ、その区間で読まれる字幕の行と一緒に送り、各行の読み始め時刻を返してもらいます。
- 次の区間は「前の区間で確認できた最後の字幕」から始めるので、ずれが積み重なりません。区間の終わり際15秒の結果は採用せず、次の区間で確かめます。
- AIが返した時刻は、近くの「声の立ち上がり」（無音→有音）に吸着させて精度を上げます。確認できなかった行は、前後の確認済みの位置から文字数で補います。
- 作品まるごとの朗読ファイルでは、各場面の最初の字幕の位置を絵の切り替え位置にします（場面の区切りも同時に直ります）。
- 結果は作品に保存されます。朗読・本文・画像の形（字幕の長さ）を変えたときだけやり直してください。未同期の場面や同期前は、v1.4 の間の検出で表示します。
- 1時間の朗読で約25回AIを呼び出します（数分〜10分程度）。途中で「止める」を押せます。
- 1時間の朗読ではブラウザが約250MBのメモリを使います。パソコンのChromeでの実行をおすすめします。

## v1.6 場面の数の指定

「本文」タブの「場面の数（絵の枚数）」で、AIで場面に分けるときの数を決めます。

- **AIのおすすめ枚数 × 倍率**（v1.7）：「AIに最適な枚数を出してもらう」で、AIが本文全体を読んで紙芝居として最適な枚数と理由を出します。それに 1倍・1.5倍・2倍・2.5倍・3倍 を掛けた枚数で分けます。おすすめ枚数をまだ出していない状態で「AIで場面に分ける」を押した場合は、先に自動で出してから分けます。本文が5%以上変わると、出し直しをすすめる表示になります。
- **場面数で指定**：2〜150場面。
- **1場面の平均時間で指定**：全体の長さ ÷ 秒数で場面数を決めます。全体の長さは、取り込んだ朗読 → 生成済みの朗読の合計 → 文字数からの目安（1秒6.5字）の順に使います。
- 指定した数と、1場面あたりの平均時間・文字数をその場で表示します。
- AIには「必ずN場面」と指示し、それでも数が違ったときは、短い場面同士をまとめる／長い場面を半分に分けて指定数に合わせます。分けた後半の場面には「前の場面の続き。構図・アングルを変えて描く」という描写を付けます。
- 場面数に対して段落が少ない本文では、文単位まで細かくしてから分けます。
- 場面を分け直すと、生成済みの絵・朗読（場面ごと）・字幕の同期結果はリセットされます。取り込んだ朗読ファイルはそのまま残るので、分け直した後に「AIで字幕を音声に合わせる」をもう一度実行してください。絵の切り替え位置も合わせ直されます。

## v1.8 動画の高速書き出し

「動画を書き出す（高速）」は、上演を再生して録画するのではなく、1コマずつ絵・字幕・音声を組み立てて WebCodecs でエンコードします。

- 実時間より何倍も速く作れます（パソコンの性能によりますが、90分の作品で数分〜十数分が目安）。進み具合・倍速・残り時間を表示し、タブのタイトルにも％を出します。
- 処理は Web Worker で動くので、**タブを裏に回したり、ほかのタブで作業していても止まりません**。ただし、パソコンがスリープすると止まります。
- 最初に保存先を選ぶと、作りながらファイルへ直接書き込みます。長い作品でもメモリを使い切りません。
- 形式は **MP4（H.264＋AAC）** を優先し、対応していない環境では MP4（H.264＋Opus）→ WebM（VP9/VP8＋Opus）の順で選びます。解像度は上演キャンバスと同じ（横長1280×720／縦長720×1280／正方形1080×1080）、24fps。
- 字幕のON/OFFと「字幕のタイミング」の設定も、そのまま動画に入ります。字幕の書体は端末の日本語ゴシック体を使います。
- WebCodecs に対応していないブラウザ（一部のスマホなど）では、これまでどおり上演しながら録画します。パソコンの Chrome / Edge を推奨します。
- `lib/` の2ファイルと `export-worker.js` も GitHub に置いてください（`index.html` と同じ階層）。

## v1.9 画面の動きをAIで付け直す

「場面と生成」タブの「画面の動き（パン・ズーム・スライド）」で設定します。

- **使う動き**：8種類（寄る・引く・左右上下へのパン・スライドで登場・動かさない）から、使うものにチェックを入れます。「動かさない」のチェックを外せば、静止した場面を作りません。設定は作品に保存されます。
- **AIで動きを付け直す**：全場面のあらすじ・場所・絵の描写をAIが読み、チェックした動きの中から場面に合う動きを付け直します（緊張や注目は寄る、余韻は引く、場所や時間が変わる場面はスライドなど）。同じ動きが3回以上続かないように整えます。
- **使わない動きだけ置き換える**：AIを使わず、チェックを外した動きになっている場面だけを、前後と重ならない動きに置き換えます。
- 「AIで場面に分ける」ときも、チェックした動きだけを使います。
- 対応表の各場面のプルダウンで、1場面ずつ手で変えることもできます。

## 制限と注意

- GAS の1回の実行は最大6分です。朗読は1場面ずつ生成するため通常は収まりますが、1場面が極端に長い場合は「場面に分ける」をやり直して細かくしてください。
- 朗読 WAV は 1分あたり約2.9MB です。上演前に全場面を読み込むため、30分程度の作品では読み込みに時間がかかります。
- 画像生成がブロックされた場合は「描写を編集」で表現を穏やかにして作り直してください。
- 入力する小説は、権利を持つもの、または著作権の保護期間が終わったものに限ってください。
